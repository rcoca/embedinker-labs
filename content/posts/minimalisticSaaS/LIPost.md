🚀 Zero-Bloat Microservices: The Reverse-Tunnel API Gateway & Self-Registering Worker Pattern

![Minimalistic SaaS architecture](minimalisticSaaS.jpeg)

If you want a resilient internal architecture without hauling in the baggage of a heavy service mesh, look no further than a reverse-tunnel worker registry backed by dynamic Protobuf schemas.

Here is how you keep it dead simple:

Hot-Reloadable Edge: Schema description files are generated by the protobuf compiler. By having the API gateway monitor a local desc folder, you achieve runtime extensibility—drop in a new descriptor, and the gateway instantly learns how to validate and translate new JSON-RPC payloads on the fly.

The Gateway IS the Registry: No separate service discovery cluster required. Workers dial into the API gateway, establishing a persistent reverse gRPC tunnel upon startup.

Built-In Heartbeats: That same reverse tunnel doubles as the heartbeat mechanism. If a worker drops connection, the gateway instantly prunes it from the active worker table.

File-Driven Worker Testing: Because business logic lives cleanly inside the workers, testing is dead simple. You can feed test inputs straight from files directly into the worker handlers without needing a mock gateway or network layer.

Secure Peer mTLS: Workers leverage mutual TLS (mTLS) for secure internal communication, allowing them to authenticate and collaborate directly when required.

Stateless Scale & Canaries: With purely stateless request-reply flows, rolling out a canary is as trivial as scaling up a fraction of new worker containers.

Clean boundaries, hot-reloadable schemas, secure peer identity, and zero external discovery dependencies.
